## 境界になる例を選ぶ
- うるう年のルールは3段階
  - 4で割り切れる → うるう年（2024年）
  - 100で割り切れる → うるう年ではない（1900年）
  - 400で割り切れる → うるう年（2000年）
- 2024年だけでは100年・400年のルールを確かめられない
- ルールの段階ごとに1つずつ例を用意する

## 月の初日・末日（core/dates.py）
- `month_date_range`で`(初日, 末日)`を返す
  - 例: `(2026-10-01, 2026-10-31)`
- 末日は`days_in_month`を再利用
  - うるう年の判定はそちらに任せる
  - テストは範囲の形だけ確かめればよい
- 12月もテストする
  - 年をまたぐ実装だとバグが出やすい
- 初日の`1`は定数`FIRST_DAY_OF_MONTH`にする

## 範囲の表し方
- ① 両端を含む（今回採用）
  - `(10/1, 10/31)`
  - SQL: `BETWEEN '2026-10-01' AND '2026-10-31'`
- ② 終わりを含まない（半開区間）
  - `(10/1, 11/1)`
  - SQL: `>= '2026-10-01' AND < '2026-11-01'`
- ①を選んだ理由
  - `record_date`は時刻のない`DATE`型
  - 「初日・末日」の名前どおりで読みやすい
  - Phase 4で`between()`にそのまま渡せる
- 時刻付き（`TIMESTAMP`）なら②が安全
  - ①だと最終日の途中の時刻が漏れる

## dateクラス
- 年・月・日だけを持つ日付のクラス
  - `from datetime import date`
  - `date(2026, 10, 1)`でオブジェクトを作る
- 存在しない日付は`ValueError`
  - 例: `date(2026, 2, 30)`
- `.year` `.month` `.day`で取り出せる
- `<`で日付どうしを比較できる

## Pythonの書き方
- `-> tuple[date, date]`は戻り値の型ヒント
  - 実行時の動作には影響しない
- `_, days = ...`の`_`は使わない値を捨てる
- `return a, b`はタプルになる
  - `x, y = f()`で分けて受け取る（アンパック）

## コードの読み方
- ① 動かして入力と出力を観察する
  - REPL（`uv run python`）で試す
  - 正常・境界・不正な入力を与える
- ② ソースファイルの場所を探す
  - `datetime.__file__`で場所が分かる
  - 本体はC実装の`_datetime`
  - `_pydatetime.py`は同じ仕様のPython版
- ③ 入口（`__new__` / `__init__`）を読む
  - 入力は`def`の引数、出力は`return`
  - 特殊ケースの`if`は読み飛ばす
- ④ 呼ばれている関数を1段ずつ追う
  - 例: `_check_date_fields`
  - ①で見た挙動の理由が分かる
- 覚え方: 試す → 場所 → 入口 → 呼び出し先
